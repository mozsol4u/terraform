Feedback and Required Updates to the Azure Backup Presentation
1. Summary Slide – Presentation Flow
Prepare a summary slide at the beginning of the presentation.
Organize the overall presentation in a logical sequence:
What: What is the current situation and what are we trying to address?
Why: Why is this required, and what are the key gaps, risks, or challenges?
How: How can these gaps be addressed, and what is the proposed solution or recommendation?
Ensure the presentation follows this sequence so that the audience can easily understand the context, challenges, and proposed approach.
2. Slide 3 – Azure Backup Coverage and Limitations
Refine the wording to clearly communicate that Azure Backup provides protection for operational recovery scenarios but does not fully address all Disaster Recovery (DR) requirements.
Introduce a clear legend to distinguish the workload coverage:
3 workloads: Not covered for operational recovery.
24 workloads: Covered for both operational recovery and DR scenarios.
Clearly distinguish between operational recovery and DR capabilities.
Redesign the slide overview, if required, to make the coverage and gaps visually clear and easy to understand.
3. Slide 6 – 3-2-1-1-0 Backup Strategy
Provide a clear visual representation of the 3-2-1-1-0 backup strategy.
Map the current Azure Backup architecture against each component of the strategy.
Clearly highlight which backup copies or protection layers are currently missing in the existing setup.
Explain the industry best practices for protecting cloud workloads, particularly Azure workloads.
Identify the gaps between the current implementation and the recommended best-practice architecture.
Redesign the slide using a simple visual representation to make it easier for the audience to understand the current state, missing components, and recommended target state.
4. Slide 7 – Azure Backup Architecture and Capabilities
The current slide is confusing and needs to be restructured.
Simplify the wording and organize the content in a logical and easy-to-follow sequence.
Remove Commvault and Rubrik references, if they are not essential to the discussion.
Focus the entire slide on Azure Backup, its architecture, capabilities, limitations, and recovery approach.
Ensure the slide communicates the Azure Backup solution clearly without unnecessary complexity or vendor comparisons.
5. Slide 22 – Azure Ransomware Recovery Scenarios
Clarify why Azure recovery is marked as Partial for certain IaaS and PaaS workloads in the ransomware recovery scenario.
Specifically explain the limitations or missing capabilities for:
IaaS workloads.
Azure Files.
Azure Blob Storage.
Azure Database for PostgreSQL – Flexible Server.
Clearly identify what is missing or not natively covered by Azure Backup in each scenario.
Introduce a detailed legend explaining what Full, Partial, and Not Covered mean.
Distinguish between backup availability, point-in-time recovery, ransomware recovery, and the ability to restore workloads into a clean or isolated environment.
Make the limitations explicit so the audience understands why certain workloads have only partial recovery capabilities.
6. Additional Slide – Azure Backup Subscription Model and Limitations

Prepare a dedicated slide to describe the proposed architecture where:

A separate Azure subscription is dedicated to Azure Backup services.
Azure Backup is enabled for all applicable workloads across the remaining Azure subscriptions.
Backup policies, vaults, protection configurations, and recovery operations are managed through the dedicated backup subscription where supported.

Clearly explain the following:

How the centralized backup subscription architecture would work.
How workloads from multiple Azure subscriptions can be protected.
Cross-subscription backup and recovery capabilities and prerequisites.
Required permissions, RBAC roles, and administrative boundaries.
Limitations related to cross-subscription and cross-region backup and recovery.
Potential impact on recovery operations if the backup subscription is compromised or unavailable.
Security considerations, including immutability, soft delete, resource locks, and protection against unauthorized deletion.
Cost, operational overhead, and management considerations.
Any Azure Backup service-specific limitations or workloads that cannot be protected using this centralized approach.

Expected outcome: The presentation should clearly communicate the current backup coverage, identified gaps, Azure Backup capabilities and limitations, industry best practices, and the recommended target architecture. The content should be technically accurate, visually clear, and understandable to both technical and management audiences.
